## 1. 背景与目标

现有「战法回测」是**组合级系统回测**：输入=自选股票池 × 战法（含仓位管理、开仓上限、加仓、3浪3动态仓位），输出=组合净值曲线/总收益/回撤。它衡量的是"我这批手挑的票，配这套系统，整体表现如何"，带有强烈的选股偏差。

本次要做的是把度量单位从**组合**降到**单个买点信号**：

> 某个买点（如"回调一半""MA60支撑""波段50%"）在**全市场**每次出现时，如果照它买、按规则管理，能给出可操作空间（盘中浮盈 ≥ +10%）的概率有多大，以及结果分布如何。

这是从"我的票整体表现"到"这个买点本身有没有优势(edge)"的转变。

### 目标（v1）
- 全市场扫描买点：**扣抵量均线支撑、5日均量均线支撑、回调一半、波段50%**（一次可多选，共享扫描）。
- 每个买点输出：样本数、成功率、大/小胜利占比、止损占比、平均持有天数、期望收益、结果分布。
- 每笔交易带上下文标签（短/长期均线状态、市值档位、行业），**导出带全量配置的明细**供离线研究。
- 保留现有的**条件单买入形式**与**开盘/盘中/收盘价对进场与止损的影响**。

### 非目标（v1 明确不做）
- 仓位大小、开仓上限、本金、加仓、3浪3 动态仓位 —— 全部丢弃（组合层概念）。
- 21日高点、MA突破拉回等其余买点 —— 后续扩展。
- 删除旧的组合回测代码 —— 仅从侧边栏隐藏入口，代码保留。
- **导入比对页面** —— phase 2；v1 只保证导出格式带全量配置，为其铺路。

## 2. 核心概念

- **买点(BuyPoint)**：一个进场触发（复用 `src/marketreview/tools/buy_points.py` 的 checker），自带触发价与专属止损。
- **band(波段)**：`band_analysis.py` 的结果。找出 P(波峰)/V(前波谷) 及回撤线（回调一半、50%线、62.5%线）。是"回调一半""波段50%"两个买点的**定价依据**；"均线支撑"（扣抵量/5日均量两变体）几乎不用 band。
- **episode(一笔交易)**：一次"建仓→出场"。**持仓中不重复建仓**——同一只票在持仓期间不再产生新交易。
- **成功(胜)**：一笔交易的**盘中最大浮盈 MFP ≥ +10%**（阈值可配）。成功再分两档：
  - **大胜利**：MFP 摸到 +20% → +20% 止盈。
  - **小胜利**：MFP 曾 ≥ +10%，之后回落到 +5% → +5% 止盈。

## 4. 逐日两阶段模型（心脏）

模拟真实交易日。每只股票逐个交易日 T：

### 🔔 盘中阶段（对当日 OHLC 做反应）——仅当持仓 或 有条件单

**A. 有持仓 → 出场判断（先止损优先）**

按发生顺序检查，命中即卖并结束该 episode：

1. **开盘(open)**：
   - `open ≤ 空间止损价` → 卖 @open（止损）
   - 否则 `open ≥ 买入价×1.20` → 卖 @open（大胜利）
   - 否则 MFP 已 ≥10% 且 `open ≤ 买入价×1.05` → 卖 @open（小胜利回落）
2. **盘中(用 high/low)**：先用 high 更新 MFP，再判：
   - `low ≤ 空间止损价` → 卖 @止损价（**止损优先**）
   - 否则 `high ≥ 买入价×1.20` → 卖 @买入价×1.20（大胜利）
   - 否则 MFP 已 ≥10% 且 `low ≤ 买入价×1.05` → 卖 @买入价×1.05（小胜利回落）
3. **收盘(≈14:57，按 close 执行)**：
   - **时间止损（通用可配）**：持有 ≥ N 交易日（默认 20，可配）→ 卖 @close
   - **买点专属收盘止损**：`close < 专属收盘止损价` → 卖 @close
     - 均线支撑：跌破 MA
     - 回调一半 / 波段50%：跌破买入价

> **空间止损价（通用可配，对三买点统一）**：由配置决定——
> 启用 ATR 时 = `买入价 − ATR倍数×ATR`；未启用时 = `买入价 ×(1 − 空间止损幅度%)`。

> T+1 约束：建仓当日不可卖出（MFP 从建仓当日起用 high 记录，但出场从建仓次日起生效）。

**B. 有条件单（且空仓）→ 成交判断**
- `open > 目标价 且 open ≤ 开盘上限` → 按 open 成交（追高）
- 否则 `low ≤ 目标价 ≤ high` → 按目标价成交
- 成交 → 转持仓；未成交 → 条件单当日作废

### 🔚 盘后阶段（15:00 之后的功课）——按"当前是否持仓"分流

1. **有持仓 → 啥也不干**（当天该卖的已在盘中/收盘执行；持仓期不看过滤器）。
2. **空仓 → 闸2 挂单资格**（**含当天刚卖出的**——卖出后即恢复扫描，当天盘后就能计划次日新单，是一笔新 episode）：
   - **过滤器（便宜，先挡）**：均线多空排列？市值区间？行业白/黑名单？上市时长？波段比例？——任一不过 → 结束，不挂单。
   - **波段 + 买点触发**：算 band(截至 T) → 跑选中的 checker → 得触发价 + 专属止损。
   - **涨跌停可达性**：目标价必须落在**次日涨跌停幅度内**才挂（主板/中小板 10%、创业板/科创板 20%、北交所 30%），否则不挂。
   - 挂条件单：`{目标价, 开盘上限=目标价×开盘追高上限%, 专属止损}`，等次日盘中阶段判成交。

**闸1（持仓判断）在最前**：持仓中整天只做出场跟踪，过滤器/买点一律不看；一旦出场（哪怕就在当天）立即恢复扫描、当天盘后即可挂次日单。

## 5. 单笔交易模拟器 `trade_sim.py`

从 `broker.py` 抽出的纯逻辑，**无 shares / 无 cash**，只算百分比。

**输入**：信号日 T、目标价、开盘上限、专属止损规则集（盘中止损价 + 收盘止损规则）、判赢/止盈参数、该股票 T 之后的日线序列。

**输出 `TradeResult`**：
```
buy_point_type   买点类型
code / name
signal_date      信号日 T
entry_date/price 进场日/价（T+1 成交；未成交则本 TradeResult 不产生）
exit_date/price  出场日/价
exit_reason      大胜利 / 小胜利 / 盘中止损 / 收盘止损 / 时间止损
mfp_pct          盘中最大浮盈%
hold_days        持有交易日数
pnl_pct          实现盈亏%
success          bool（mfp_pct ≥ 判赢阈值，默认10%）
── 信号时上下文标签（供导出/分组研究，均在信号日 T 记录）──
short_ma_state   短期均线状态：多头 / 空头 / 盘整
long_ma_state    长期均线状态：多头 / 空头 / 盘整
market_cap_yi    信号日市值（亿）
cap_bucket       市值档位：微盘(<100) / 小盘(100~300) / 中盘(300~600) / 大盘(>600)
industry_l1/l2   行业分类（L1/L2 名称）
```
> 标签让导出后可任意切片研究（如"只看大盘股 × 长期多头下的回调一半胜率"）。

未成交的条件单**不计入样本**（只统计真正进场的交易）。可选：单独记未成交计数用于观察挂单命中率，不进胜率分母。

## 6. 过滤器框架 `filters.py`

每个过滤器 = `(code, date, df_截至date, industry, mv_asof) → bool`，可组合、可在配置开关。在**收盘阶段、空仓时**评估一次。

| 过滤器 | v1 | 说明 |
|---|---|---|
| 短期均线排列 | ✅ | MA5/MA10/MA20；状态=**多头**(MA5>MA10>MA20 且向上)/**空头**(反向且向下)/**盘整**(其余)。**可多选允许的状态**，留空=不限 |
| 长期均线排列 | ✅ | MA60/MA120/MA240；同上三态，**可多选**，留空=不限（与短期独立开关） |
| 市值区间 | ✅ | 用**补齐历史市值**按时点过滤；配置 `市值下限亿 / 市值上限亿`。四档（微盘<100 / 小盘100~300 / 中盘300~600 / 大盘>600）作为每笔交易的**标签**导出，不作为过滤条件 |
| 行业白/黑名单 | ✅ | L1/L2 级，来自 `stock_industry_cache`，用 `\|` 组合 |
| 上市时长 | ✅ | 上市 ≥ N 天，剔次新 |
| 波段比例 | ✅ | 买点内已隐含（V/P、跌破62.5%等），可作为显式开关 |

> 均线"多头"= 三线从上到下依次排列且均线方向向上；"空头"= 反向且向下；"盘整"= 其余（含数据不足）。每组**可多选允许的状态**（如长期选「多头+盘整」= 非空头），留空=不限。短期、长期两组独立。

## 7. 买点接入（v1 三个）

复用 `buy_points.py` 的 checker，包一层适配器，提供"触发价 + 专属止损"。专属止损沿用 `_calc_stop_losses` 已算好的值：

| 买点 | checker | 阶段 | 需要 band | 盘中空间止损 | 收盘止损（专属） |
|---|---|---|---|---|---|
| 扣抵量均线支撑 | `MAChecker(vol_mode="today")` | trial | 否 | 通用配置（见 §8） | 跌破 MA |
| 5日均量均线支撑 | `MAChecker(vol_mode="avg5")` | trial | 否 | 通用配置（见 §8） | 跌破 MA |
| 回调一半 | `HalfRetraceChecker` | live | ✅ | 通用配置（见 §8） | 跌破买入价 |
| 波段50% | `Band50Checker` | live | ✅ | 通用配置（见 §8） | 跌破买入价 |

> 盘中空间止损对四个买点**统一**用 §8 配置（固定% 或 N×ATR）；只有收盘止损按买点专属。均线买点需 MA 值、回调/波段需买入价作为收盘止损参照。

> **两个均线支撑变体**只差"放量确认"用哪个量（均只用信号日 T 及更早，无未来函数）：`扣抵量均线支撑` 用**当日成交额**，`5日均量均线支撑` 用**近5日均量**；其余（均线向上 + 支撑 + 扣抵量/后续均量对比 + 收盘跌破MA止损）完全一致，由 `MAChecker(vol_mode=…)` 参数化，逻辑不复制。

> **阶段开关（live/trial）**：`BaseBuyPointChecker.STAGE` 默认 `live`；两个均线支撑变体设 `trial`。`find_all_buy_points`（个股追踪/波段分析）默认**过滤掉 trial**，买点胜率作为试验台照常全收。`config/buy_point_config.txt` 的 `显示试验买点=1` 可临时把 trial 买点放开到那两页；买点"毕业"时把 `STAGE` 改回 `live`，一处生效。

> 适配器需支持 walk-forward 调用：在历史某日 T，用截至 T 的数据算 band 与买点（不能看未来）。

## 9. 输出与页面 `06_买点胜率.py`

**运行模型**：一次可**多选买点**，共享同一次全市场扫描（扫描时同时检测多种买点触发），过滤/止损/时间配置对所有买点一致 → 横向对比最公平。

**配置区**：多选买点、过滤器设置、判赢阈值、通用止损、时间范围、并发数。

**运行（硬性要求：并发 + loading 进度）**：
- 扫描按**单只股票多线程并发**（`ThreadPoolExecutor`，并发数可配，沿用旧回测页做法）。
- 运行时显示 **loading 进度条 + 实时文案**（已完成/总数、当前阶段），沿用现有 `st.progress` + `st.empty` 模式。

**结果展示——按买点分开**（每个买点一个**独立区块**，绝不混在一起）。每块含：
- **概览指标**：触发次数(样本数)、**胜率**(大+小)、**大胜利** 数/率、**小胜利** 数/率、**止损**(盘中空间止损) 数/率、**亏损**(收盘/时间止损侧) 数/率、平均持有天、期望收益。
- **分布图**：该买点 mfp / pnl 直方图（plotly）。
- **明细（默认收起，按股票分组）**：放在该买点区块下方的 `st.expander`（默认折叠）。点开后逐笔记录**以股票为维度分组**——每只票聚合它在该买点下的所有 episode（同一票不同时间可有多笔），便于定位单票**复盘**。每票内按信号日排序；含 票/进出场/原因/mfp/pnl/标签，沿用现有 HTML 表格渲染与**红涨绿跌**配色。

**顶部对比汇总表**（横向一览，每买点一行，方便一眼对比）：

| 买点 | 触发次数 | 胜率 | 大胜利率 | 小胜利率 | 止损率 | 亏损率 | 平均持有天 | 期望收益 |
|---|---|---|---|---|---|---|---|---|

> 出场分桶（互斥，按 `exit_reason`）：**大胜利 / 小胜利 / 盘中止损 / 收盘止损 / 时间止损**。胜率 =（大胜利+小胜利）/ 触发次数；"止损"指盘中空间止损，"亏损"指收盘止损+时间止损中最终为负的部分（非负者另记"平/微赚"）。

### 9.1 数据导出与跨运行比对

- **导出（v1）**：一次运行可导出，**按买点分开**——每个买点单独一份明细文件（不同买点的记录**绝不混在一起**，便于分开研究）。每份含两部分：
  - **运行元数据头**：本次配置全量（买点、过滤器、判赢/止盈/止损/时间参数、扫描时间窗、运行时间戳、数据快照日）。
  - **明细**：该买点的每笔 `TradeResult`（含上下文标签 short_ma_state/long_ma_state/market_cap_yi/cap_bucket/industry）。**按股票分组排序**（`code` 为主键、信号日次之），导出后也能直接按票复盘。
  - 命名建议：`winrate_<买点>_<时间窗>_<导出时间>.csv`，配置头同名 `.json` 或作为 CSV 顶部注释块。

## 12. 性能与风险

- **band 逐日计算量**：最坏 5600 票 × ~680 天很重。缓解顺序：闸1持仓跳过 → 闸2过滤器先挡（便宜）→ band 只在过滤通过时算；band 窗口限长（如最近 250 日）。**先跑单行业小样本测耗时**，再决定是否加缓存/降采样。
- **盘中路径歧义**：同日既触止盈又触止损 → **先止损**（保守，胜率不高估）。
- **未来函数**：所有指标（MA/ATR/band）在日 T 只能用截至 T 的数据；适配器必须 walk-forward，禁止全序列一次算完再回看。
- **前复权一致性**：K线先 `raw_to_qfq` 再算指标（与项目其余部分一致）。
- **市值静态 vs 历史**：v1 采用补齐历史市值；补齐失败的早期区间该股当日市值过滤按"缺失"处理（放行或剔除，配置决定，默认放行并记警告）。
