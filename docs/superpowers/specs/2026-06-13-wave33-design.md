# 33 Formula (Wave 33) Design Spec

**Date:** 2026-06-13
**Status:** approved
**Scope:** 3浪3选股扫描 + 市场全景 UI 集成

---

## 1. Overview

Implement the "33 Formula" — a stock screener that identifies A-shares in strong main-lift-wave (主升浪) phase. The count of qualifying stocks and its trend serve as a market breadth / profitability gauge, displayed on the Market Overview page.

---

## 2. Formula Rules

### 2.1 Input Per Stock

- **Window:** 40 trading days of daily K-line (前复权). Minimum 25 days required
  (WR(20) needs 20 periods before first valid value + 5 check days).
- **Scan universe:** All 沪深A股, excluding:
  - Currently suspended (当日无交易)
  - ST / *ST stocks
  - Stocks listed < 300 trading days

### 2.2 Five Conditions (all must be met)

| # | Name | Formula | Meaning |
|---|------|---------|---------|
| 1 | `KD80` | K(9,3,3) > 80 | K value in overbought zone |
| 2 | `WR3` | WR(10) < 20 **AND** WR(20) < 20 | Dual Williams %R high-level passivation |
| 3 | `RSI70` | RSI(9) > 70 | RSI confirming strength |
| 4 | `MKT_CAP` | Market cap > 100万 (万元) | Exclude micro-cap |
| 5 | `LIST_DAYS` | Listed > 300 trading days | Exclude recent IPOs |

### 2.3 Final Signal

```
XG: COUNT(BASE, 5) = 5
```

All 5 conditions must hold **for 5 consecutive trading days** — confirms sustained strength.

### 2.4 20-Day Profit

Among stocks meeting XG today, count how many closed higher than 20 trading days ago.

---

## 3. Output

### 3.1 Per Trading Day (stored in wave33_cache)

| Field | Type | Description |
|-------|------|-------------|
| `wave33_count` | int | Number of stocks meeting XG on that day |
| `profit_count` | int | Of those, how many up vs 20d ago |
| `profit_pct` | float | profit_count / wave33_count * 100 |
| `stock_codes` | JSON | `{"all": [...], "profit": [...]}` — codes for cumulative computation |

### 3.2 Chart Display (rolling cumulative)

Each of the **15 chart bars** represents a target date D. The bar value for D is the
**cumulative unique union** of all stocks that passed XG in the 21-trading-day window
`[D-20td, D]` (i.e., D and the preceding 20 trading days).

This rolling 21-day window means:
- Bar values can rise (new stocks enter window) or fall (stocks exit window)
- Trend analysis and red/green bar colors remain meaningful
- Example: 2026-06-12 bar = unique stocks passing on any day from 2026-05-15 to 2026-06-12

### 3.3 Trend Analysis

Logic applied to the rolling cumulative `wave33_count` series (most-recent-first):

| Consecutive Direction | Label |
|----------------------|-------|
| < 3 days | 维持上升/下降，盘整中 |
| 3–4 days | 暂时上升/下降，连续上升/下降 N 天 |
| ≥ 5 days | 确认上升/下降，连续上升/下降 N 天 |

### 3.4 Historical Cache

Store daily result in SQLite so the chart can be rendered without re-scanning.
Scan 40 trading days (15 chart + 21 rolling window + margin) to ensure the earliest
bar has a full 21-day window.

### 4.3 Data Layer — Separation of Concerns

| Layer | Responsibility | File |
|-------|---------------|------|
| **ensure_data_loaded()** | 拉取 K线 + 市值 (`daily_basic.total_mv`)，附带股票列表初始化 | `data_provider.py` / `cache_manager.py` |
| **stock_basic** | 首次运行时拉一次全市场列表（沪深A股 code/名称/上市日），持久缓存 | 同上 |
| **wave33.py** | **纯计算**：读缓存 → 运行 5 条件 × 5 天 → 写 `wave33_cache` | `tools/wave33.py` |

### 4.4 Data Provider Additions

- `DataProvider.get_stock_list()` — 沪深A股列表，优先读缓存，缓存为空则调 `stock_basic` API 拉一次
- `DataProvider.get_market_cap(trade_date)` — 某日全部股票市值，走 CacheManager 缓存
- `ensure_data_loaded()` — 扩展：K 线拉取完成后，追加拉取对应日期范围的 `daily_basic` 市值数据

### 4.5 Dashboard Integration

- **Console page (00_控制台.py):** After `ensure_data_loaded()`, call `ensure_wave33_computed()` — scans 40 trading days. Also runs on quick-return path (when K-line + daily_basic cache is fresh). Uses `st.status` with progress callback showing date + stock count.
- **Market panorama (01_市场全景.py):** `DashboardService.get_wave33_data(chart_days=15, rolling_days=21)` — reads from SQLite cache, computes rolling 21-day cumulative per bar, returns 15 data points. No computation in the render path.

## 5. Data Flow

```
User selects trade_date in Console
  → ensure_data_loaded(trade_date)          # K-line + daily_basic (市值), stock_basic on first run
  → ensure_wave33_computed(trade_date)       # 纯计算，读缓存不调 API
    → Determine last 40 trading days up to trade_date (15 chart + 21 window + margin)
    → For each day NOT in wave33_cache (most-recent first):
      → dp.get_stock_list() → 从缓存过滤 ST/次新/停牌
      → dp.get_market_cap(that_day) → 读缓存
      → For each stock: dp.get_daily(code, 40d ending at that_day) → 读缓存，qfq
      → Run 5 conditions × 5 days per stock (纯计算)
      → Compute profit count vs 20d ago
      → INSERT into wave33_cache（stock_codes = {"all": [...], "profit": [...]}）

User navigates to 市场全景
  → DashboardService.get_wave33_data(chart_days=15, rolling_days=21)
    → SELECT last 36 rows from wave33_cache  (read-only)
    → For each date D, compute cumulative union over [D-20td, D]
    → Return last 15 entries for chart
  → 01_市场全景.py renders Plotly chart + sidebar card
```

## 6. Caching & Reuse Strategy

### Two-level cache:

1. **K-line cache (existing):** `tushare_cache` table via CacheManager — per-stock daily data fetched once, reused across all scans
2. **Wave33 result cache (new):** `wave33_cache` table — per-date aggregate result, computed once in console, read many times in rendering

### New table:

```sql
CREATE TABLE IF NOT EXISTS wave33_cache (
    trade_date  TEXT PRIMARY KEY,
    count       INTEGER NOT NULL,
    profit_count INTEGER NOT NULL,
    profit_pct  REAL NOT NULL,
    stock_codes TEXT,          -- JSON array of qualifying codes
    updated_at  TEXT DEFAULT (datetime('now'))
);
```

### Reuse pattern:
- **Batch backfill:** On each console run, check the last 40 trading days — compute any missing days in `wave33_cache`, most-recent first. This ensures enough history for 15 chart bars × 21-day rolling window.
- Each trade date computed ONLY once
- Rendering pages never trigger computation — read from cache only, compute rolling cumulative in-memory
- K-line data per stock already cached by CacheManager before scan begins
- Subsequent visits to an already-computed date range: instant
- `stock_codes` stores `{"all": [...], "profit": [...]}` JSON for cumulative union computation

## 8. Edge Cases

- **Market holiday:** No scan, chart shows last N trading days
- **< 15 days of history:** Chart shows whatever is available
- **No stocks qualify:** Count = 0, profit = 0, trend = "维持，盘整中"
- **ST list change:** Re-fetch stock list on each scan
- **Newly listed stocks:** Excluded until listed ≥ 300 trading days
